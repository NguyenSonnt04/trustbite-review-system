# Validation

## Proof Strategy

Use proof-first/TDD in baby steps. TB-AWS-001 should not be marked implemented
until each claimed provider path has recorded proof and unsupported paths are
explicitly named. The first implementation slice should prefer the smallest
provider with real LocalStack support, most likely S3, before attempting
Textract, Cognito, SES, or Bedrock.

Do not use production AWS credentials for routine validation. Do not claim live
AWS proof unless the environment, commands, costs, and cleanup path are accepted
for that run.

## Test Plan

| Layer | Cases |
| --- | --- |
| Unit | AWS config parses endpoint, region, force path style, allow lists, and credentials from env without source literals; provider selection fails closed outside allowed local/test modes; provider errors map to structured app errors. |
| Integration | S3 LocalStack create/put/get/delete through the same config/service boundary; Textract adapter command construction and normalized mapping; Cognito JWT/JWKS/admin behavior through accepted test doubles when LocalStack cannot prove it; SES/Bedrock adapter tests if those boundaries are introduced. |
| E2E | Not required for this platform story unless a user-visible flow is added by a future story. |
| Platform | `npm run docker:up`; LocalStack health query; record supported services and unsupported gaps; cleanup temporary resources. |
| Performance | No broad benchmark required; provider retries/timeouts should be bounded when introduced. |
| Logs/Audit | Verify no raw tokens, credentials, receipt bytes, or PII-heavy provider responses are logged by new provider code. |

## LocalStack Proof Plan

1. Start infrastructure with `npm run docker:up`.
2. Query `http://localhost:4566/_localstack/health` and record service support.
3. Run a targeted S3 smoke through the application S3 config/service boundary:
   create a temporary bucket/object, read or verify it, delete it, and remove the
   bucket/object with no residue.
4. Attempt Textract LocalStack proof only if the health/support output and local
   tier support the needed API. Otherwise record the exact unsupported gap and
   keep proof at unit/test-double/syntax level.
5. Keep Cognito proof on Cognito-compatible JWT/JWKS/admin test doubles unless a
   supported provider environment exists for the exact behavior.
6. For SES and Bedrock, add proof only when a story introduces the boundary or a
   supported local/live provider is available.

## Fixtures

- Local-only AWS endpoint such as `http://localhost:4566`.
- Local-only AWS credentials supplied by env.
- Temporary S3 bucket/object names generated by tests or env-specific prefixes,
  never source literals.
- Cognito-compatible JWKS/tokens for JWT validation tests.
- Mock Textract, SES, and Bedrock responses that are clearly named test doubles
  and fail closed outside allowed local/test environments.

`npm run verify:tb-aws-localstack` starts Docker/LocalStack, polls LocalStack
health for S3 and SES, logs unclaimed provider statuses for Cognito IdP,
Textract, and Bedrock, runs a static AWS SDK provider-boundary audit, runs
targeted S3/config/SES/Textract/Cognito unit proof, runs the S3 receipt storage
LocalStack smoke through the application service boundary with a Vitest `-t S3`
filter, runs the Cognito LocalStack support classification smoke with a Vitest
`-t Cognito` filter, runs the SES LocalStack smoke through the messaging
provider boundary with an injected LocalStack SES client, and runs
`npm run server:build`. This command verifies the accepted local provider
boundary contract without claiming Textract, Cognito, or Bedrock LocalStack/live
provider success where support is missing.

## Acceptance Evidence

## 2026-07-08 First S3 LocalStack Slice

Implemented the first proof slice for S3-only LocalStack/config boundaries.
`server/src/config/aws.js` now applies the shared endpoint fallback
`AWS_ENDPOINT_URL || LOCALSTACK_ENDPOINT_URL` to `awsConfig.s3.endpoint`, so
receipt storage and other S3 clients use the same local provider endpoint
boundary when LocalStack is configured through `LOCALSTACK_ENDPOINT_URL`.

Red proof:

- `npm run test --prefix server -- tests/unit/config/awsConfig.test.js` failed
  before implementation because `config.s3.endpoint` stayed `undefined` when
  only `LOCALSTACK_ENDPOINT_URL=http://127.0.0.1:4566` was configured.

Green proof:

- `npm run test --prefix server -- tests/unit/config/awsConfig.test.js` passed
  with 1 file / 2 tests after the config fix.
- `npm run test --prefix server -- tests/unit/config/awsConfig.test.js tests/unit/storage/objectStorage.test.js tests/unit/receiptStorageService.test.js`
  passed with 3 files / 8 tests.
- `npm run docker:up` started `trustbite-localstack`.
- `Invoke-WebRequest -UseBasicParsing http://127.0.0.1:4566/_localstack/health`
  reported LocalStack community `4.4.0` with `s3`, `ses`,
  `secretsmanager`, and related core services available; Cognito IdP and
  Textract were not reported as available in the health response.
- With `RUN_LOCALSTACK_PROVIDER_SMOKE=true`,
  `LOCALSTACK_ENDPOINT_URL=http://127.0.0.1:4566`, local test credentials, and
  no `AWS_ENDPOINT_URL`, `npm run test --prefix server -- tests/integration/providerCleanupLocalStack.integration.test.js`
  passed with 1 file / 3 tests. The new S3 smoke creates a temporary bucket,
  uploads through `s3ReceiptStorageService.uploadReceiptObject`, verifies the
  object with LocalStack S3, deletes through
  `s3ReceiptStorageService.deleteReceiptObject`, verifies the object is gone,
  and removes the temporary bucket.
- `npm run server:build` passed syntax check for 102 files.
- `npm run verify:tb-aws-s3` passed after adding the dedicated S3 LocalStack
  verifier script. The verifier's integration phase runs
  `tests/integration/providerCleanupLocalStack.integration.test.js -t S3`, which
  passed 2 S3 tests and intentionally skipped the non-S3 Cognito blocker test.
- `npm run harness -- story verify TB-AWS-001` passed with verify command
  `npm run verify:tb-aws-s3`.

Proof classification:

- S3: partial story proof complete for this slice via unit config proof and
  LocalStack create/upload/verify/delete cleanup through the application S3
  receipt storage boundary.
- Textract: unchanged; unit/adapter proof only from existing stories, no
  LocalStack or live AWS `AnalyzeExpense` proof claimed here.
- Cognito: unchanged; existing JWT/JWKS/admin behavior remains test-double
  backed unless supported LocalStack/pro or live AWS proof is provided.
- SES: unchanged; LocalStack health reports SES available, but no TrustBite SES
  adapter smoke was introduced in this slice.
- Bedrock: unchanged; no local/live provider proof.

TB-AWS-001 remains high-risk and `in_progress`, not implemented, because only
the first S3 provider-boundary slice has proof.

## 2026-07-08 Boundary Audit And Unsupported Gap Closeout

Implemented the final provider-boundary closeout for the accepted local
contract. `scripts/audit-aws-provider-boundaries.mjs` walks `server/src` and
fails if AWS SDK imports or `new *Client(...)` instantiation appear outside
`server/src/config/` or `server/src/services/`.

Red proof:

- `node scripts/audit-aws-provider-boundaries.mjs` failed before implementation
  with `MODULE_NOT_FOUND`, proving the verifier had no durable boundary-audit
  guard.

Green proof:

- `node scripts/audit-aws-provider-boundaries.mjs` passed with
  `AWS SDK provider boundary audit passed.`
- `npm run verify:tb-aws-localstack` passed after adding the boundary audit,
  Textract/Cognito targeted unit proof, OCR mapping proof, Cognito support
  classification smoke, and unclaimed provider status logging. The final verifier started
  Docker/LocalStack, confirmed `s3=running` and `ses=running`, logged
  `cognito-idp=missing`, `textract=missing`, and `bedrock=missing`, passed the
  AWS SDK provider boundary audit, ran 7 targeted unit files / 55 tests, passed
  S3 LocalStack smoke with 2 S3 tests and 1 skipped non-S3 test, passed Cognito
  LocalStack support classification with 1 Cognito test and 2 skipped non-Cognito
  tests, passed SES LocalStack smoke with 1 test, and passed `server:build` for
  103 files.

Final proof classification:

- Boundary: AWS SDK client placement is guarded by the verifier. Current source
  instantiates provider clients only under `server/src/services/` or config.
- S3: LocalStack provider proof complete for the accepted local slice.
- SES: LocalStack provider-boundary proof complete for send smoke with an
  injected local client; product email workflow and live AWS SES are not claimed.
- Textract: targeted unit proof covers adapter command construction and mapping.
  LocalStack/live `AnalyzeExpense` success remains unclaimed because health
  reports `textract=missing`.
- Cognito: targeted unit/test-double proof covers JWT/JWKS/admin boundary, and
  LocalStack support classification records the current emulator gap instead of
  claiming Cognito LocalStack success.
- Bedrock: documented unsupported gap; no SDK/runtime adapter or local/live
  proof is claimed.

TB-AWS-001 is implemented for the accepted local provider-boundary contract:
LocalStack proof is claimed only for supported S3 and SES paths, while Textract,
Cognito, and Bedrock provider gaps are explicit and do not pretend to be local
or live-AWS proof.
